## What we chose to build, and why

**One artifact this week**, following the "quality over quantity"
bar: one world-class primitive beats three mediocre ones. The batch
contains `skillcheck` and nothing else.

**`skillcheck`** -- offline safety linter for agent skill files.
Zero-dep Python (stdlib only), MIT. Direct response to the frontier
signal at [1] below: arXiv 2608.05223 ("Towards a Risk Assessment
of Malicious Skill Files in Coding Agents", 2026-08-05) demonstrates
that coding agents can be induced to execute adversarial shell
commands embedded in natural-language skill files, and calls for
skill-interface risk mitigation tooling. `skillcheck` is the small
pre-flight primitive that answers "does the skill inventory of this
repository contain risky patterns before I load it?" entirely
offline, in a form that runs as a CLI, a pre-commit hook, or a CI
check.

Ten documented rules: destructive shell (SKILLCHECK-001), privilege
escalation (SKILLCHECK-002), network exfiltration / reverse shell
(SKILLCHECK-003), credential and secret reference (SKILLCHECK-004),
obfuscation and hidden-character control (SKILLCHECK-005),
prompt-injection payload markers (SKILLCHECK-006), runtime
install-and-execute (SKILLCHECK-007), filesystem archive
exfiltration (SKILLCHECK-008), undeclared-capability skill files
(SKILLCHECK-009), and suspicious external URL references
(SKILLCHECK-010). 151 tests across the pattern library
(positive-and-negative per family), rule engine (structural
SKILLCHECK-009 plus text-driven SKILLCHECK-001..010), scanner
(discovery / size caps / BOM stripping / latin-1 fallback / repo
caps / deterministic ordering), CLI (exit codes / --json / --strict
/ --include-info / --version / single-file / missing-path stderr /
default cwd), report formatters (JSON parseability + determinism +
info toggle + exit-code mapping incl. strict-mode), and end-to-end
fixture smoke tests for six distinct skill-repo shapes (safe /
shell / exfil / obfus / injection / unknown).

The lab's hygiene-linter family already covers file-contents hygiene
(`envcheck`, `jsonlcheck`, `jwtcheck`), eval-stream hygiene
(`jsonldiff`, `jsonlsample`), install-manifest hygiene (`reqcheck`),
license-chain hygiene (`licensechain`), and contribution-policy
hygiene (`aicontribcheck`). `skillcheck` extends the family to
*agent-skill hygiene* -- the pre-flight surface that an agent
runtime about to load a skill inventory needs to consult before
making the attempt.

We considered secondary candidates this cycle (deferred `injscan`
pre-flight prompt-injection scanner motivated by arXiv 2607.20759
"IssueTrojanBench", and a new candidate `logintrap` login-inducement
detector motivated by arXiv 2608.04741) and declined for the
"quality over quantity" reasons: `skillcheck` warranted the full
week's attention. Both remain deferred.

## Signal we noted (not built this week)

1. **Towards a Risk Assessment of Malicious Skill Files in Coding
   Agents** (arXiv 2608.05223, 2026-08-05). Demonstrates agents
   execute adversarial shell commands embedded in skill files;
   explicitly calls for skill-interface risk mitigation tooling.
   The paper's *framing* is the direct motivation for `skillcheck`;
   the paper's methodology, benchmark, and any reference code was
   NOT consulted. [arXiv](https://arxiv.org/abs/2608.05223)

2. **LoginTrap: Phishing-Style Indirect Prompt Injection** (arXiv
   2608.04741, 2026-08-05). Task-agnostic login-inducement achieves
   86% end-to-end success; identifies authentication boundary risk
   as a distinct attack surface. Implies a complementary primitive:
   an offline detector for login-inducement markers in agent tool
   responses (deferred; a "logintrap" detector for the response
   text an agent is about to consume).
   [arXiv](https://arxiv.org/abs/2608.04741)

3. **Permission Literacy in Mobile GUI Agents** (arXiv 2608.04755,
   2026-08-05). MLLMs grant over-privileged permissions due to
   task-prior override and app-trust bias. Implies a manifest-hygiene
   primitive analogous to `licensechain` / `aicontribcheck` but for
   mobile app manifests (deferred; the mobile-manifest angle is
   further from the lab's current core).
   [arXiv](https://arxiv.org/abs/2608.04755)

4. **PromptShield Home: Multimodal Prompt Injection Defense**
   (arXiv 2608.05495, 2026-08-06). Smart-home scenarios expose
   disjoint failure modes between detectors and MLLMs; single-layer
   detection reaches only 76.5% while oracle routing reaches 94.1%.
   Signals the multi-detector routing pattern as an emerging
   defensive frontier -- noted but not directly buildable as a
   small primitive.
   [arXiv](https://arxiv.org/abs/2608.05495)

5. **Resume Means Resume: Conformance Contract for Workflow
   Persistence** (arXiv 2608.03836, 2026-08-04). Formal TLA+
   contract for checkpoint-resume semantics; reveals five workflow
   frameworks silently violate their own resume claims. Implies a
   `resumecheck` conformance-linter primitive (deferred; needs a
   specific target-framework surface to be worth building).
   [arXiv](https://arxiv.org/abs/2608.03836)

6. **Fail-Fast, Restart-Smart: Early Failure Prediction and
   Restart** (arXiv 2608.03222, 2026-08-04). Lightweight 0.6B
   monitor predicts SWE-agent failure from prefixes and enables
   cost-saving restarts. Not directly buildable as a small
   zero-dep primitive -- requires a model.
   [arXiv](https://arxiv.org/abs/2608.03222)

7. **EA-Graph: Artifact-Anchored Verification Memory for Coding
   Agents** (arXiv 2608.04278, 2026-08-04). Artifact-anchored
   claim memory to prevent stale verification assertions across
   repository drift. A promising primitive framing but the
   graph-store infrastructure is heavier than a small stdlib
   primitive.
   [arXiv](https://arxiv.org/abs/2608.04278)

8. **An Exploratory Study of Agent Plans for Agentic AI Coding
   Tools** (arXiv 2608.04661, 2026-08-05). Only 85 agent-plan
   artifacts found across 36K repositories -- sparse adoption of
   the plan-file surface. Implies eventual demand for a plan-file
   linter but the surface is too immature to build against yet.
   [arXiv](https://arxiv.org/abs/2608.04661)

9. **EffiHolmes / RepoEffi-Bench** (arXiv 2608.03558, 2026-08-04).
   First repository-level time-inefficiency benchmark (140 Python
   issues); prior tooling focused on functional bugs. Signals that
   performance-bug localisation is now benchmark-tractable.
   Interesting but not directly buildable as a small primitive
   without a Python profiling harness that itself needs
   integration.
   [arXiv](https://arxiv.org/abs/2608.03558)

10. **Active-SWE: Benchmarking Coding Agents for Proactive Bug
    Fixing** (arXiv 2608.04682, 2026-08-05). Benchmark for agent
    bug discovery *without* issue reports; exposes weak proactive
    localisation across current agents. Signals the "no issue,
    still find the bug" surface as unmet capability.
    [arXiv](https://arxiv.org/abs/2608.04682)
