# Research Radar -- 2026-07-19

Weekly digest of frontier signal in AI / ML / software, scanned roughly
2026-07-13 -> 2026-07-19 across arXiv (cs.SE, cs.LG-with-`abs:evaluation`,
cs.PL), Show HN, and aggregated developer-pain complaint data. Items are
noted, not endorsed; source links are for verification.

## What we chose to build, and why

**One artifact this week**, following the "quality over quantity" bar:
one world-class primitive beats three mediocre ones. The batch contains
`reqcheck` and nothing else.

**`reqcheck`** -- offline supply-chain hygiene linter for `pip`-style
requirements files. Zero-dep, MIT. Direct response to the frontier
signal below at [1]: arXiv 2607.15143 ("Setup Complete, Now You Are
Compromised", 2026-07-16) frames AI coding agents' habit of installing
dependencies without pre-flight verification as a systematic supply-
chain risk vector. `reqcheck` is the small primitive that answers "is
this manifest hygienic?" *before* `pip install` runs. Nine documented
rules: pin discipline (REQ-A001), hash discipline (REQ-A002), typosquat
shape via Damerau-Levenshtein against a curated widely-installed-
package snapshot (REQ-A003), duplicate declarations (REQ-A004),
`--trusted-host` TLS-bypass (REQ-A005), VCS URL without pinned commit
SHA (REQ-A006), non-ASCII / homograph in name (REQ-A007), editable
local install red-flag (REQ-A008), and custom-index informational
notice (REQ-A009). 87 tests across parser, rules, typosquat, and CLI.

The prior weeks' JSONL / dotenv hygiene family (`jsonlcheck`,
`envcheck`, `jsonldiff`, `jsonlsample`, `jwtcheck`) covers file-contents
hygiene; `reqcheck` extends the theme to install-manifest hygiene.

We considered building a second artifact this cycle (candidates below
under "Deferred to next cycles") and declined: the brief's guidance is
1-3 artifacts, with a strong preference for one excellent over multiple
mediocre; `reqcheck` warranted the full week's attention.

## Signal we noted (not built this week)

1. **Setup Complete, Now You Are Compromised** (arXiv 2607.15143,
   2026-07-16). Empirical study of AI coding agents installing
   dependencies without verifying names, sources, or vulnerabilities.
   The paper frames install-time supply-chain exposure as its own risk
   surface, distinct from post-install execution. This is the direct
   motivation for `reqcheck`; we are not building any part of the
   paper's method, only the small pre-install primitive its framing
   implies is missing from most developer setups.
   [arXiv](https://arxiv.org/abs/2607.15143)

2. **Quantize with Confidence?** (arXiv 2607.14181, dual-submitted to
   cs.PL and cs.LG). Empirical framework for measuring the impact of
   post-training quantization on generated code quality across
   McEval / CoderEval. Small extractable idea: a diff-and-summarize
   primitive for "same benchmark, two model outputs" that treats
   syntactic vs semantic equivalence as separate axes. Not built this
   week; would need a hosted-model loop to demonstrate honestly.
   [arXiv](https://arxiv.org/abs/2607.14181)

3. **Leaf: Dynamic Analysis Framework for Rust** (arXiv 2607.15025).
   Instrumentation-based analysis at the compiler-plugin level; large
   in scope by design. Noted as a signpost for the *"the Rust
   dynamic-analysis story is still early"* frame, not for direct
   reimplementation.
   [arXiv](https://arxiv.org/abs/2607.15025)

4. **Proof-or-Stop Lifecycle Control** (arXiv 2607.14890). Evidence-
   gated lifecycle transitions for autonomous coding agents: an agent
   cannot claim a state transition without fresh, mechanically
   verifiable evidence. The idea is architecturally close to the
   contract-and-harness theme we tracked last week [7]; still too
   abstract for a small primitive.
   [arXiv](https://arxiv.org/abs/2607.14890)

5. **Why Git Is the Memory Solution for the Agentic Development
   Lifecycle** (arXiv 2607.14390). Argues that git already provides
   the durable, inspectable, resumable memory substrate that agentic
   workflows need. Compact enough that a git-anchored retrieval-over-
   commit-messages primitive might be extractable; the paper's own
   contribution is retrieval-over-commits, so a clean-room primitive
   here would need to be motivated by, not derived from, this work.
   Deferred.
   [arXiv](https://arxiv.org/abs/2607.14390)

6. **Optimal Combination of Binary Classifiers** (arXiv 2607.14889).
   Explicit analytical formulae for the optimal linear combination of
   binary classifier outputs via truth-table partitioning, with
   stability characterization through φ-frontiers. Testable in
   principle but not obviously useful as a standalone primitive
   without accompanying benchmark harness; noted.
   [arXiv](https://arxiv.org/abs/2607.14889)

7. **On the Correctness of Software Merge** (still-relevant follow-up
   from prior cycle: arXiv 2607.07987). Category-theoretic correctness
   for merge = parsability + incorporation of all edits. Composes
   naturally with the drift-detection theme of `reqcheck`: a lint that
   catches merge-artifact leftovers (e.g., `<<<<<<<` conflict markers
   in a requirements.txt) is a two-hour extension. Provisionally next
   cycle if a real user needs it.
   [arXiv](https://arxiv.org/abs/2607.07987)

8. **Show HN this cycle: LoFT (LLM training without GPU)**, **Sifaka
   (LLM output critique)**, **AI File Sorter**, various AI-first
   product launches. Sharp signal on the *state of consumer-agent
   packaging*, low signal on new dev-tooling primitives worth cloning.
   No item selected.

## Methodology this cycle

- arXiv `export.arxiv.org/api/query` for cs.SE / cs.PL and cs.LG-
  filtered-by-`abs:evaluation`, sorted by submitted-date descending;
  ~70 titles across the 2026-07-13 -> 2026-07-19 window.
- HN Algolia `search_by_date` for `"Show HN"` in the same window plus
  a keyword search for `security OR audit OR lint OR cli` -- the
  latter returned zero hits above the >100-points threshold, so the
  signal was almost entirely from arXiv this cycle.
- Triage filter unchanged from prior weeks: *can a small clean-room
  implementation actually be tested this run, without a hosted-model
  dependency?* Of ~70 arXiv titles surveyed, one (2607.15143) directly
  implied a small primitive we could ship at world-class quality this
  run. The rest are noted or deferred.
