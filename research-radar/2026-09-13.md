## What we chose to build, and why

**One artifact this week**, holding the standing quality-over-quantity bar.
The batch contains `mcpservercheck` and nothing else.

**`mcpservercheck`** -- offline static linter for MCP-server
*registration* configuration files -- the JSON / JSONL that a user
pastes into an MCP client to install a server (`.mcp.json`, `mcp.json`,
and the `mcpServers` / `servers` / `mcp.servers` blocks). Zero-dep
Python stdlib, MIT.

The direct motivation is that the MCP-security literature has converged
across three independent surfaces on the same observation: the *runtime*
authorization and prompt-injection defences that MCP clients ship cannot
recover from a *registration config* whose command is a shell interpreter
with an inline-eval flag, whose transport is plaintext HTTP, whose `env`
value inlines a bearer literal, whose command line has a remote-fetch-and-
execute pattern, whose args reference an unpinned package ref, and whose
permissions are wildcarded.

1. **Public CVE record.** CVE-2025-54136 ("MCPoison") is the empirical
   demonstration that a client that binds trust to an MCP-registration
   key name rather than the underlying command it launches can be
   pivoted by silently mutating what the key points to. CVE-2025-54135
   ("CurXecute") chains indirect prompt injection with auto-starting new
   MCP-registration entries. Both faults are recoverable only by
   registration-time hygiene -- the runtime does not know which command
   was originally intended.

2. **Systematic threat modelling.** arXiv 2603.22489 ("Model Context
   Protocol Threat Modeling and Analyzing Vulnerabilities to Prompt
   Injection with Tool Poisoning") systematised the analysis across
   seven widely-used MCP clients and named a defence stack of static
   metadata validation, parameter visibility, injection detection,
   execution sandboxing, and audit logging. The static-metadata layer
   is not a solved problem in current clients; that gap is where
   `mcpservercheck` fits.

3. **Protocol-level analysis.** arXiv 2601.17549 ("Breaking the
   Protocol: Security Analysis of the Model Context Protocol
   Specification and Prompt Injection Vulnerabilities in Tool-Integrated
   LLM Agents") identified three protocol-level weaknesses -- absence of
   capability attestation, bidirectional sampling without origin
   authentication, and implicit trust propagation in multi-server
   configurations. The multi-server-trust-propagation finding motivates
   MSC-005 (structurally-incomplete server entries), MSC-008 (wildcard
   permissions), and MSC-010 (bare-binary-name PATH-hijack advisory).

4. **Quantified empirical surface.** Public reporting through Q3 2026
   documents 14+ CVEs against MCP implementations, an estimated
   ~200,000 servers potentially compromisable through SDK flaws, and a
   ~2,614-implementation survey finding that 82% use file operations
   prone to path traversal, 67% use APIs related to code injection, and
   34% use APIs susceptible to command injection. The volume validates
   the pre-flight primitive.

`mcpservercheck` reads the registration file the client will consume and
flags ten shape defects: interpreter-with-eval-flag command (MSC-001),
plaintext transport (MSC-002), inline bearer literal in env (MSC-003),
remote-fetch-and-execute pattern in command line (MSC-004), structurally
incomplete server entry (MSC-005), unpinned package reference in args
(MSC-006), credential-shape env key with inline value (MSC-007),
wildcard in permissions / allowedTools / env passthrough (MSC-008),
command from world-writable temp directory (MSC-009), bare binary name
command (MSC-010 -- INFO, PATH-hijack advisory hidden by default).
Five HIGH, four MEDIUM, one INFO. Verdict rollup, deterministic exit
codes, `--json` for CI, `--strict` / `--include-info` / `--disable
RULE_ID` per-repo overrides, exactly as in the other members of the
lab's hygiene-linter family.

205 tests: 10 types tests (Severity / Verdict enums + Finding immutability
+ sort-key ordering + tiebreak-by-path-line-col-rule + ScanResult defaults),
23 parser-helper tests (offset-to-line-col across LF / negative / overflow,
find_key with from-offset, BOM stripping via escape-sequence constant, JSON
/ JSONL loading, snippet truncation and newline-flattening), 10 rule-registry
invariants (count == 10 + id uniqueness + canonical MSC-NNN + non-empty
descriptions + valid severities + 5/4/1 HIGH/MEDIUM/INFO split + check-fns
callable + healthy-fires-nothing + empty-dict-no-findings + container-shape
variants), per-rule positive+negative across all ten rules with
adversarial-vs-clean discrimination (11 MSC-001, 6 MSC-002, 11 MSC-003
including a generated-at-runtime 48-char high-entropy token assembled from
sub-16-char parts, 7 MSC-004, 4 MSC-005, 7 MSC-006, 8 MSC-007, 6 MSC-008,
6 MSC-009, 7 MSC-010, plus 2 bare-top-level-detection tests), 20 scanner
tests (read_text UTF-8 / BOM-strip / latin-1 fallback / max-bytes cap;
discover missing / single-file glob-match / miss / dir walk / case-
insensitive / max-files cap / deterministic sort / custom glob; scan_file
json healthy / json unhealthy / jsonl per-line / invalid-json-no-crash /
disable-suppresses; scan_path empty / findings-sorted / disable-suppresses
/ max-files-bound; plus DEFAULT constant invariants), 17 verdict-and-report
tests (rollup no-files-unknown / high-unhealthy / medium-needs-attention /
high-beats-medium / info-default-healthy / info-strict-needs-attention /
no-findings-healthy; exit-codes 0/1/2 across verdicts; text verdict-line +
totals + hides-info-by-default + shows-info-with-include-info + lists-
errors; JSON parseable / deterministic / omits-info-by-default / includes-
info-when-configured / errors-field), 11 CLI tests (--version / --list-
rules / missing-path / healthy-dir / unhealthy-dir / no-files-default /
no-files-strict / --json / --include-info / --disable-flips-verdict /
--max-files-0 / --max-bytes-0 / --glob-extends-default), 14 end-to-end
fixture tests across ten adversarial fixture shapes plus healthy plus
unknown plus a generated-at-runtime secret fixture (secret-shaped
strings ASSEMBLED at runtime from sub-16-char parts, never as verbatim
literals in source) plus a JSON-roundtrip determinism verification plus
a global cross-fixture sort-order invariant, and 3 python-dash-m
invocation tests validating `python -m mcpservercheck --version`,
`--list-rules`, and healthy-fixture-exit-zero.

Dogfood: running `mcpservercheck examples/weak_mcp.json` yields
verdict=unhealthy, exit 2, ten findings across 5 HIGH (MSC-001, MSC-002,
MSC-003, MSC-004, MSC-005) and 4 MEDIUM (MSC-006, MSC-007, MSC-008,
MSC-009) plus 1 INFO (MSC-010 -- hidden by default; visible with
`--include-info`) -- proof that the primitive fires cleanly on a config
that stitches every rule into one adversarial file. Same tool on
`examples/healthy_mcp.json` yields verdict=healthy, exit 0, zero findings.

The lab's hygiene-linter family covers file-content hygiene (`envcheck`,
`jsonlcheck`, `jwtcheck`), eval-stream hygiene (`jsonldiff`, `jsonlsample`),
install-manifest hygiene (`reqcheck`), license-chain hygiene
(`licensechain`), contribution-policy hygiene (`aicontribcheck`), agent-
skill safety hygiene (`skillcheck`), agent-instruction maintainability
hygiene (`agentmdlint`), test-oracle-shape hygiene (`oraclecheck`), agent-
consumed-content hygiene (`elevatescan`), and agent-delegation config
hygiene (`delegcheck`). `mcpservercheck` adds the **MCP-server
registration** layer: `delegcheck` scans the delegation *graph* the
harness will honour (who delegates to whom, with what credential scope,
with what depth cap); `mcpservercheck` scans the *registration* the
client will load (how a server is installed, what interpreter it runs,
what transport it uses, what env it receives). Two orthogonal surfaces
of the same runtime.

## Signal we noted (not built this week)

1. **CVE-2025-54136 "MCPoison"** -- trust bound to MCP-registration key
   name rather than to the underlying command it launches. Motivation
   for MSC-010 (bare-binary-name PATH-hijack advisory) and MSC-005
   (structural completeness invariants for the client to bind trust
   against a real target).
   [advisory summary](https://the-agent-report.com/2026/07/mcp-security-landscape-2026-vulnerabilities-mitigations/)

2. **CVE-2025-54135 "CurXecute"** -- chained indirect prompt injection
   with auto-starting new MCP-registration entries. Reinforces that a
   registration-time hygiene pass is the correct trust boundary; runtime
   defences cannot recover a config that was maliciously injected before
   the client rebooted.
   [advisory summary](https://the-agent-report.com/2026/07/mcp-security-landscape-2026-vulnerabilities-mitigations/)

3. **Breaking the Protocol: Security Analysis of the Model Context
   Protocol Specification and Prompt Injection Vulnerabilities in
   Tool-Integrated LLM Agents** (arXiv 2601.17549). Three protocol-level
   weaknesses: absence of capability attestation, bidirectional sampling
   without origin authentication, implicit trust propagation across
   multi-server configurations. Motivates MSC-005, MSC-008, MSC-010.
   [arXiv](https://arxiv.org/abs/2601.17549)

4. **Model Context Protocol Threat Modeling and Analyzing Vulnerabilities
   to Prompt Injection with Tool Poisoning** (arXiv 2603.22489). Named
   the defence-stack layers (static metadata, parameter visibility,
   injection detection, execution sandboxing, audit logging) and
   observed the static-metadata layer as under-implemented across seven
   surveyed clients. Direct motivation for `mcpservercheck`.
   [arXiv](https://arxiv.org/abs/2603.22489)

5. **Are AI-assisted Development Tools Immune to Prompt Injection?**
   (arXiv 2603.21642). Empirical measurement of prompt-injection
   susceptibility across AI-assisted dev tools; contextual reinforcement
   that MSC-004 (remote-fetch-and-execute) is a real deployment shape,
   not a theoretical one.
   [arXiv](https://arxiv.org/abs/2603.21642)

6. **ClawGuard: A Runtime Security Framework for Tool-Augmented LLM
   Agents Against Indirect Prompt Injection** (arXiv 2604.11790). A
   runtime layer that complements a pre-flight registration linter --
   noted as an intended composition, not a substitute.
   [arXiv](https://arxiv.org/abs/2604.11790)

7. **Trust No Tool: Evaluating and Defending LLM Agents under Untrusted
   Tool Feedback** (arXiv 2605.17453). Formalises the "tool output is
   untrusted DATA" model; independently justifies the honesty-as-floor
   discipline that lab-published tools follow (ingested content never
   an instruction).
   [arXiv](https://arxiv.org/abs/2605.17453)

8. **Prompts Don't Protect: Architectural Enforcement via MCP Proxy for
   LLM Tool Access Control** (arXiv 2605.18414). Argues that in-model
   prompt-based access control is not defence-grade; access control
   must be architectural. Motivates MSC-003 and MSC-007 (secret shape
   is a proxy for architectural rather than in-model access control).
   [arXiv](https://arxiv.org/abs/2605.18414)

9. **MCP Security in Q3 2026: 14 CVEs, 200,000 Exposed Servers**
   (public reporting). Quantifies the surface: ~7,000 MCP servers
   publicly reachable; ~200,000 servers estimated potentially
   compromisable through SDK flaws; ~2,614-implementation survey
   with 82% path-traversal-prone file ops, 67% code-injection-adjacent
   APIs, 34% command-injection-susceptible APIs.
   [MCP security landscape report](https://the-agent-report.com/2026/07/mcp-security-landscape-2026-vulnerabilities-mitigations/)

10. **The Ultimate Guide to MCP Security Vulnerabilities**
    (industry writeup, 2026). Consolidates context-poisoning,
    weak-authentication, transport-security, and command-injection
    threat classes. Complements the arXiv literature with practitioner
    framing.
    [aembit.io writeup](https://aembit.io/blog/the-ultimate-guide-to-mcp-security-vulnerabilities/)

11. **NSA / DoD CSI: Model Context Protocol Security guidance**
    (June 2026). Government-issued security guidance for MCP. Framing
    signal that the surface is broadly acknowledged as production-
    critical.
    [CSI PDF](https://media.defense.gov/2026/Jun/02/2003943289/-1/-1/0/CSI_MCP_SECURITY.PDF)

12. **Cloud Security Alliance -- Agentic MCP Security Best Practices**
    (v1, 2026). Practitioner-consensus best-practices for MCP
    deployment; independent framing of the same shape defects
    `mcpservercheck` linters against.
    [CSA lab space](https://labs.cloudsecurityalliance.org/agentic/agentic-mcp-security-best-practices-v1/)

13. **Snyk Labs: Prompt Injection Meets MCP** (2026). Vendor-published
    threat writeup framing prompt-injection-via-tool-output as a new
    exploitation vector. Reinforces MSC-004 (remote-fetch-and-exec) as
    a real production shape.
    [Snyk Labs writeup](https://labs.snyk.io/resources/prompt-injection-mcp/)

14. **Hacker News community signal** -- Show HN threads for AI-agent
    control-layer tooling (G0), MCP risk-analysis directories
    (armor1.ai), and MCP command-injection blog exploitations
    continue to appear at a steady cadence. Independent confirmation
    that the MCP-registration-file surface is a live community need.
    `mcpservercheck` targets a distinct layer (registration static
    linter) that is orthogonal to runtime governance dashboards.
