### `pjhookcheck` -- static linter for package.json lifecycle-hook and install-time supply-chain shapes

The direct motivation is that three independent evidence surfaces have
now converged on the same finding: the `preinstall` / `install` /
`postinstall` / `prepare` script fields of `package.json` are a running
arbitrary-code execution point that is entered every time a user runs a
plain install, and the current defensive posture is broadly
undertriaged.

1. **Public field incident.** On 2026-09-18 Arch Linux disclosed that
   more than 400 AUR packages had been compromised via `postinstall`
   malware sourced from the npm registry. The compromise did not
   require attacker control of package *content* at first-install
   time; the lifecycle hook alone was the delivery mechanism.

2. **Published research.** arXiv 2609.03884 ("A Blind Trust, the
   Bloody Thrust") measured that lifecycle-hook configuration alone
   was enough to compromise all seven evaluated AI coding-agent
   harnesses, with per-harness success rates up to 92.5 percent.
   Static defences were only partly effective.

3. **Empirical prevalence.** arXiv 2609.07360 ("Scanning the Harness")
   scanned 3,171 repositories and found 16.0 percent carried a security
   defect in the install path, with install-time hooks shipping without
   a lockfile or a pre-install check.

The three surfaces together establish that the fault class is real,
current, and empirically prevalent, and that a pre-flight linter over
the specific fields the hook mechanism reads is the correct
intervention. `pjhookcheck` reads a `package.json` before it is
committed or installed and reports twelve install-time shape defects:

- **PJH-001..006 (HIGH)**: hook fetches and executes remote code
  (`curl | sh`, `iwr | iex`, `Invoke-WebRequest | Invoke-Expression`);
  hook uses an inline-eval interpreter flag (`node -e`, `python -c`,
  `sh -c`, `bash -c`, `powershell -Command`); hook decodes an encoded
  blob into an exec site (`base64 -d | sh`, `Buffer.from(...,'base64')`,
  long `atob(...)`); dependency specifier is a git or tarball URL;
  `file:` dependency escapes the repository root; hook references a
  sensitive user or system path (`~/.ssh/`, `~/.bashrc`, `~/.npmrc`,
  `~/.aws/`, `/etc/`, `/usr/`).
- **PJH-007..011 (MEDIUM)**: hook installs a package globally; hook
  prints an env var with a credential-shape name (`echo $NPM_TOKEN`,
  `printf %s ${GITHUB_TOKEN}`); dependency version has no security
  floor (`latest`, `*`, `x`, `>=0.0.0`); `bundleDependencies` is
  present (transitive deps hidden from the lockfile); hook body is
  heavily obfuscated (dense hex escapes, 400+ character single line,
  200+ character base64-shape run).
- **PJH-012 (INFO)**: `packageManager` field absent; corepack cannot
  pin the CLI (hidden by default; visible under `--include-info`).

The `6 HIGH / 5 MEDIUM / 1 INFO` split matches the lab's other
hygiene-linter members. Verdict rollup, deterministic exit codes,
`--json` for CI, `--strict` / `--include-info` / `--disable RULE_ID`
per-repo overrides, exactly as in `mcpservercheck`, `sarifcheck`, and
`nbshape`.

Dogfood: running `pjhookcheck examples/weak_package.json --include-info`
yields verdict=unhealthy, exit 2, findings across every one of the
twelve rules. Same tool on `examples/healthy_package.json` yields
verdict=healthy, exit 0, zero findings.

The lab's hygiene-linter family now covers file-content hygiene
(`envcheck`, `jsonlcheck`, `jwtcheck`), eval-stream hygiene
(`jsonldiff`, `jsonlsample`), install-manifest hygiene (`reqcheck`,
`licensechain`), contribution-policy hygiene (`aicontribcheck`), agent-
skill hygiene (`skillcheck`), agent-instruction maintainability
hygiene (`agentmdlint`), test-oracle-shape hygiene (`oraclecheck`),
agent-consumed-content hygiene (`elevatescan`), agent-delegation config
hygiene (`delegcheck`), MCP-server registration hygiene
(`mcpservercheck`), security-scan-output hygiene (`sarifcheck`), and
notebook-reproducibility hygiene (`nbshape`). `pjhookcheck` adds the
**install-time** layer: `mcpservercheck` scans the registration a
client will load for an MCP server; `pjhookcheck` scans the package
manifest that runs on any consumer's machine at `npm install` time.
Two orthogonal surfaces of the same root-cause class ("author-supplied
command runs on consumer's machine before any application code
imports").

## Method note

The artifact is an independent implementation built from public
specification text (npm and pnpm docs on `scripts` and dependency-URL
specifiers), from named public field incidents (the AUR 400-package
post-install compromise; the Shai-Hulud v2 and `pino-SDK-v2`
exfiltration campaigns), and from published findings (arXiv 2609.03884,
arXiv 2609.07360). No reference implementation of an install-hook
linter was read, vendored, or mirrored. Not affiliated with nor
endorsed by any package manager, registry, or research group. Offline
and stdlib-only: it reads a `package.json`, reports shapes, executes
nothing it reads, and opens no network connection.

As always, a linter reports shapes. It cannot detect an attack, and a
clean run is not a safety certificate.
