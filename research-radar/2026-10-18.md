### `devcontainercheck` -- static linter for devcontainer.json files

Two independent 2026-10 signals converged on the same surface - the
**developer-facing dev-container config at container-create time** -
and together establish a current unmet need the lab's hygiene-linter
family can serve directly.

1. **The GhostAction supply-chain campaign (2026-10-07 -> 2026-10-09).**
   The Hacker News reported (2026-10-09) that attackers using
   credential-stealing GitHub Actions workflows compromised over 500
   maintainer accounts and planted the malicious workflow in tens of
   thousands of repositories; GitGuardian's "GhostAction Returns"
   write-up placed the escalation at 772 confirmed repositories by
   mid-month with a 30k reach projection for October. Socket, Datadog
   Security Labs, Aviatrix, and the Cloud Security Alliance published
   independent corroborating reports in the same week. The attacker
   shape across every report was the same tag-pinned fetch-and-exec
   pattern: `uses: owner/repo@v1`, `curl ... | bash`, credentials
   inlined in CI config.
2. **GitHub Actions workflow lockfiles entered public preview
   (October 2026).** The feature pins actions to commit SHAs instead
   of mutable tags; coverage across DEV.to, Datadog Security Labs,
   BuildMVPFast, Decryption Digest, and Ciphers Security framed the
   fault class as "mutable-tag supply-chain source". The response
   named the shape explicitly: **immutable pin or supply-chain risk**.

The GitHub Actions workflow surface is YAML and out of scope for a
stdlib-only linter. The sibling surface - **`devcontainer.json` and
`.devcontainer/<name>/devcontainer.json`** - is **JSON (JSONC)** and
carries the same shape family across its own six lifecycle slots
(`initializeCommand`, `onCreateCommand`, `updateContentCommand`,
`postCreateCommand`, `postStartCommand`, `postAttachCommand`), its
`features` block, its `containerEnv` / `remoteEnv` / `build.args`
blocks, its `mounts` and `runArgs` arrays, and its `image` field.
Every finding class the week's news coverage named has a direct
devcontainer-side shape: curl-pipe (DC-001), unpinned VCS install
(DC-002), unpinned feature reference (DC-003), inlined credential
(DC-004), hidden-character class in a shell string (DC-005), sensitive
host-path mount (DC-006), privileged runArgs (DC-007), shell-init
mutation (DC-008), host-env leak via `${localEnv:...}` (DC-009),
mutable image tag (DC-010); plus two INFO rules on root-user default
(DC-011) and missing-name silent-change surface (DC-012).

VS Code's Workspace Trust gate exists precisely because
devcontainer.json runs code on folder open; GitHub Codespaces and the
Dev Containers CLI run those commands unconditionally. The 2026-10
GhostAction evidence confirms the shape family matters now; the
devcontainer surface is where the lab's charter can meet it.

`devcontainercheck` is the small offline pre-flight that catches the
twelve shape defects *before* the dev container runs. 5 HIGH / 5
MEDIUM / 2 INFO. 120 tests pass under `python -m unittest discover -s
tests`; every rule has positive-and-negative discrimination; the
shared package-surface contract against `docs/CONVENTIONS.md` is
locked; the cp1252-console reporter invariant is locked by a
subprocess test. Independent implementation, not affiliated with or
endorsed by Microsoft, the containers.dev working group, or any
cited security publication.

  this lab's stdlib-only charter. The right home is a different lab
