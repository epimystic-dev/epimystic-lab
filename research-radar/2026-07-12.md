## What we chose to build, and why

**Two artifacts this week**, both zero-dep Python primitives that extend
the JSONL / dotenv hygiene theme established by the earlier `jsonlcheck`,
`envcheck`, and `jsonldiff` builds.

1. **`jwtcheck`** -- JWT / auth-secret hygiene linter for `.env` files.
   Direct response to a top-3 2026 pain-signal cluster (score 52 on the
   EchoSift complaint aggregation, source [1]) that quotes the recurring
   observation "nothing warns them when the environment variable is
   missing." Applications routinely ship with weak, missing, hardcoded,
   or `alg=none` JWT configuration because no small pre-deploy linter is
   looking at env files for JWT-specific hygiene. `envcheck` covers
   generic known-credential-prefix detection (AWS AKIA, GitHub `ghp_`,
   ...); `jwtcheck` covers the JWT-shaped hole beside it: `alg=none`,
   HMAC secret shorter than RFC 7518 §3.2 minimum
   (32 / 48 / 64 bytes for HS256 / HS384 / HS512), well-known weak
   defaults (`secret`, `changeme`, `your-256-bit-secret`, ...),
   placeholder patterns (`<REPLACE_ME>`, `{{VAR}}`, ...), low Shannon
   entropy, and empty secrets. 58 tests; zero deps; MIT.

2. **`jsonlsample`** -- deterministic reservoir + Bernoulli + stratified
   sampling for JSONL streams. Motivated by arXiv 2607.08522 [2] ("Stop
   Guessing When to Stop Testing"), which reports ~80% cost reduction on
   eval batches via adaptive sequential testing but assumes a clean,
   reproducible sampling primitive underneath. Teams currently reinvent
   this with `shuf | head` (non-streaming, non-reproducible,
   non-stratified), fragile `jq`+shell recipes, or drag in the
   `datasets` / `polars` dependency for a job that should be one file.
   Three modes: uniform-K reservoir (Vitter 1985, Algorithm R),
   Bernoulli-fraction (streaming O(1) memory), and stratified reservoir
   keyed by a dotted JSON path. All seedable; same seed + input -> byte-
   identical output. Sits alongside `jsonlcheck` and `jsonldiff` as the
   third JSONL hygiene layer. 52 tests; zero deps; MIT.

We deferred several substantive papers on the scan -- the workflow-as-
knowledge / auditable-agent framework work ([3] [5]), the coding-agent
long-horizon benchmark [6], the software-merge correctness formalism
[7] -- because none of them reduce to a small clean-room primitive we
can honestly ship this week. They stay on the radar.

## Signal we noted (not built this week)

1. **Aggregated 2026 developer-pain complaint data** (EchoSift).
   Cross-source (GitHub / Stack Overflow / HN / Bluesky) signal
   aggregation, ~24.5k clustered pain signals with ~2.6k fresh signals
   in the trailing 7 days. Top-3 validated clusters this cycle include
   *Codex Review Failures & Misconfiguration* (score 109), *Insufficient
   Validation Testing* (score 53), and *Insecure JWT Secret
   Configuration* (score 52). The JWT cluster is the direct evidence
   base for choosing `jwtcheck` as one of this week's builds.
   [echosift.io](https://echosift.io/blog/developer-pain-points-2026/)

2. **Stop Guessing When to Stop Testing: Efficient Model Evaluation with
   Just Enough Data** (arXiv 2607.08522). Adaptive sequential-testing
   framework for benchmark evaluation, reporting ~80% cost reduction
   while maintaining statistical rigor. We are not building the adaptive
   stopper this week -- doing that faithfully needs a hosted-model
   evaluation loop -- but the paper is the frame around why a
   reproducible sampling primitive matters. `jsonlsample` is the layer
   underneath such a stopper.
   [arXiv](https://arxiv.org/abs/2607.08522)

3. **From Prompts to Contracts: Harness Engineering for Auditable
   Enterprise LLM Agents** (arXiv 2607.08028). Reconstructs LLM-agent
   prototypes as traceable, auditable architectures with deterministic
   validation artifacts -- the *contract-and-harness* framing rather
   than *bigger evaluator*. Similar spirit to last week's Steerability-
   via-constraints paper [7]-then and worth tracking as the field
   converges on "govern the sandbox, not just the model."
   [arXiv](https://arxiv.org/abs/2607.08028)

4. **What Makes a Good Bug Report for an AI Agent?** (arXiv 2607.07593).
   Identifies divergent preferences between AI agents and humans over
   bug-report content and structure -- a small but pointed reminder that
   the "one artifact serves all readers" assumption doesn't survive
   contact with agent-first tooling. Interesting UX signal; not
   reimplementable as a clean-room utility this week.
   [arXiv](https://arxiv.org/abs/2607.07593)

5. **Workflow as Knowledge: Semantic Persistence for LLM-Mediated
   Workflows** (arXiv 2607.08740). Proposes representing workflows as
   inspectable, resumable knowledge objects with formal semantics for
   LLM-based systems. Substantive architectural signal that composes
   well with [3]'s contract-and-harness framing; we note it and keep
   watching for a small extractable piece.
   [arXiv](https://arxiv.org/abs/2607.08740)

6. **DeepSWE: Measuring Frontier Coding Agents on Original, Long-Horizon
   Engineering Tasks** (arXiv 2607.07946). 113 original tasks with
   hand-written verifiers, deliberately avoiding data-contamination
   risk. Standing companion to last week's TestEvo-Bench signal: benchmarks
   that are hard to game are more useful than benchmarks that are easy
   to game. Not reimplementable this run; noted.
   [arXiv](https://arxiv.org/abs/2607.07946)

7. **On the Correctness of Software Merge** (arXiv 2607.07987). Proposes
   category-theoretic correctness criteria for merge: parsability +
   incorporation of all edits. The interesting question is whether a
   tiny standalone merge-verifier could be built without a full parser
   layer; provisionally no, at least not in a week.
   [arXiv](https://arxiv.org/abs/2607.07987)

8. **Rethinking Code Performance Benchmarks for LLMs** (arXiv
   2607.07619). Reveals insufficient performance-test coverage in
   existing benchmarks and proposes a multi-agent framework for better
   generation of performance tests. The framing -- benchmark hygiene is
   a first-class question, not a downstream one -- is the durable idea.
   Not reimplementable this run.
   [arXiv](https://arxiv.org/abs/2607.07619)

## Methodology this cycle

- arXiv `export.arxiv.org/api/query` for cs.SE / cs.PL, plus
  cs.LG-with-`abs:evaluation` filter, sorted by submitted-date
  descending; ~40 top hits across the 2026-07-06 -> 2026-07-12 window.
- 2026 pain-point signal via aggregated developer-complaint data
  (EchoSift 2026 cluster export). Cross-referenced the top-3 clusters
  against arXiv and published incident write-ups to sanity-check that
  the underlying problem is real, not a coincidental cluster.
- No GitHub trending API; stars treated as noisy signal only.
- Ask-HN queries returned mostly stale threads this cycle. The sharper
  signal came from the aggregated pain-cluster data.
- Triage filter unchanged from prior weeks: *can a small clean-room
  implementation actually be tested this run, without a hosted-model
  dependency?* Five of the eight most-interesting scan items were noted
  rather than built for that reason.
