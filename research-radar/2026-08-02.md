## What we chose to build, and why

**One artifact this week**, following the "quality over quantity" bar:
one world-class primitive beats three mediocre ones. The batch
contains `aicontribcheck` and nothing else.

**`aicontribcheck`** -- offline AI-contribution-policy detector for
open-source repositories. Zero-dep Python (stdlib only), MIT. Direct
response to the frontier signal at [1] below: arXiv 2607.26819 ("A
First Look at Coding Agents' Compliance with AI Contribution Rules
in Open-Source Communities", 2026-07-29) reports that coding agents
never proactively retrieve contribution rules and cannot refuse
contributions in AI-banned repositories without explicit prompts.
`aicontribcheck` is the small pre-flight primitive that answers
"does this repo's own contribution policy permit what I am about to
do?" entirely offline, in a form that runs as an agent tool call, a
pre-commit hook, or a CI check.

Ten documented rules: explicit ban (AICONTRIB-001), explicit allow
(AICONTRIB-002), disclosure-required (AICONTRIB-003), attribution
obligation (DCO / CLA / copyright-assignment / signed-off-by)
(AICONTRIB-004), human-review-required (AICONTRIB-005),
tests-required (AICONTRIB-006), named-AI-tool mention as evidence
(AICONTRIB-007), non-commercial licence detected on LICENSE
(AICONTRIB-008), unknown-policy rollup (AICONTRIB-009), and
cross-file conflict (AICONTRIB-010). 119 tests across the pattern
library (positive-and-negative per family), rule engine, rollup
logic, scanner, CLI (exit codes / --json / --strict / --include-info
/ --version / single-file / stdin-equivalents), report formatters,
and end-to-end fixture smoke tests for five distinct policy shapes
(ban / allow / conditional / unknown / conflict).

The lab's hygiene-linter family already covers file-contents hygiene
(`envcheck`, `jsonlcheck`, `jwtcheck`), eval-stream hygiene
(`jsonldiff`, `jsonlsample`), install-manifest hygiene (`reqcheck`),
and license-chain hygiene (`licensechain`). `aicontribcheck` extends
the family to *contribution-policy* hygiene -- the pre-flight surface
that an agent about to open a PR needs to consult before making the
attempt.

We considered a second artifact this cycle (the deferred `injscan`
pre-flight prompt-injection scanner motivated by arXiv 2607.20759
"IssueTrojanBench") and declined for the second week running: the
guidance is 1-3 artifacts with a strong preference for one excellent
over multiple mediocre, and `aicontribcheck` warranted the full
week's attention. `injscan` remains deferred; its clean-room boundary
from the paper's benchmark distribution is now clearer (the
detection heuristics all trace to independent public sources -- OWASP
LLM01, the Trojan Source paper, Unicode UTS #39) but a dedicated
cycle will do it justice.

## Signal we noted (not built this week)

1. **A First Look at Coding Agents' Compliance with AI Contribution
   Rules in Open-Source Communities** (arXiv 2607.26819,
   2026-07-29). Empirical finding: coding agents never proactively
   retrieve contribution rules and cannot refuse contributions in
   AI-banned repositories without explicit prompts. The paper's
   *framing* is the direct motivation for `aicontribcheck`; the
   paper's methodology, benchmark, and any reference code was NOT
   consulted -- `aicontribcheck` is a small pre-flight primitive the
   framing implies is missing, not a re-implementation of the paper.
   [arXiv](https://arxiv.org/abs/2607.26819)

2. **PAIChecker: Uncovering and Checking PR-Issue Misalignment in
   SWE-Bench-Like Benchmarks** (arXiv 2607.28587, 2026-07-30).
   Multi-agent system detects that 13.6% of SWE-bench instances show
   misalignment between pull requests and their linked issues. Implies
   a complementary small primitive: a static "issue-PR overlap score"
   linter operating on `.md` + `diff` pairs. Noted; the paper's
   multi-agent method itself is framework-scale, but the *overlap
   score primitive* is extractable and clean-room-implementable from
   standard information-retrieval baselines. Candidate for a future
   cycle.
   [arXiv](https://arxiv.org/abs/2607.28587)

3. **ORCA-bench: How Ready Are Language Model Agents for Oncall?**
   (arXiv 2607.28545, 2026-07-30). Production-fidelity benchmark
   shows frontier coding agents achieve 25.3% accuracy on realistic
   oncall root-cause tasks. Benchmark-scale by design; noted as
   signpost for the growing "agents in operations" gap.
   [arXiv](https://arxiv.org/abs/2607.28545)

4. **Not as Sweet by Another Name: An Empirical Study of Format
   Robustness in LLM Document Workflows** (arXiv 2607.27648,
   2026-07-30). Document format variations cause accuracy drops up
   to 53.63% and trigger decision drift in 41% of LLM workflow
   instances. Implies a small primitive: a "document canonicaliser"
   that normalises markdown / HTML / plain-text into a stable form so
   LLM workflows get identical inputs regardless of format. Noted for
   a future cycle; the harder version -- a "format-drift detector"
   between two representations of the same document -- would need a
   more careful baseline.
   [arXiv](https://arxiv.org/abs/2607.27648)

5. **HALO: Heterogeneous Admission through Localized Obligations for
   Safe Agentic Execution** (arXiv 2607.27636, 2026-07-30). Runtime
   protocol claims 100% blocking of tested stale actions while
   preserving supported response components. Interesting as a
   protocol contribution; framework-scale to implement standalone.
   [arXiv](https://arxiv.org/abs/2607.27636)

6. **SIGIL: Compiling Agent Skills into Typed Harnesses** (arXiv
   2607.27309, 2026-07-29). Compiled skill harnesses achieve 86%
   step execution vs 56% for prose agents while reducing token
   consumption by 42%. Related to the "agent-skill contract linter"
   idea previously deferred. Candidate but requires more scoping.
   [arXiv](https://arxiv.org/abs/2607.27309)

7. **Send and Pretend: Exploiting Transcript Consistency Issues in
   End-to-End Encrypted Group Chats** (arXiv 2607.27510,
   2026-07-29). Malicious participants can omit or alter messages
   including poll results undetected. Domain-specific to E2E chat
   protocols; not obviously extractable as a small offline linter.
   [arXiv](https://arxiv.org/abs/2607.27510)

8. **MIND: Lightweight and Effective Memory Injection Defense for
   LLM Agents via Intent-Aware Information Bottleneck** (arXiv
   2607.28103, 2026-07-30). Framework reducing memory-injection
   attack success by 55%. Framework-scale; noted.
   [arXiv](https://arxiv.org/abs/2607.28103)

9. **Old Tricks, New Models: How Simple Image Transformations Break
   Modern AI-based Content Moderation** (arXiv 2607.28187,
   2026-07-30). Basic transformations bypass commercial moderation
   APIs with 69% success. Signal on classifier fragility rather than
   a small primitive; noted.
   [arXiv](https://arxiv.org/abs/2607.28187)

10. **Show HN: Formally verified 3D CSG: Trust 93 lines spec, not
    1000 lines AI code** (HN 49083239, 115 pts). Formally verified
    3D mesh intersection using AI-generated proofs verified against
    a small spec. Sharp signal on the *"trust the spec, not the
    generation"* pattern that motivates lints like `aicontribcheck`
    at the process layer. Noted.
    [GitHub](https://github.com/schildep/verified-3d-mesh-intersection)

## Deferred to next cycles

- **`injscan`** -- offline pre-flight prompt-injection payload scanner
  motivated by IssueTrojanBench (arXiv 2607.20759, deferred from
  2026-07-26). Ten proposed rules covering hidden-comment
  instructions, base64-decoded instruction patterns, Unicode-tag
  steganography, zero-width joiner sequences, role-shift phrases,
  confusable characters in role labels, bidi-override tricks,
  outbound data-URIs, nested code-fence role-play, and whitespace
  exfiltration channels. Detection heuristics all trace to
  independent public sources (OWASP LLM01; Boucher & Anderson's
  "Trojan Source" 2021; Unicode UTS #39). Ready for a dedicated
  cycle.
- **`pridiff`** -- static issue-PR overlap score linter motivated by
  PAIChecker (arXiv 2607.28587). Reads an issue markdown and a diff,
  computes a small overlap score, and reports whether the PR text
  actually addresses the issue text. Small, clean-room-implementable,
  useful as a self-check for an agent about to submit.
- **`fmtcanon`** -- document canonicaliser motivated by 2607.27648.
  Normalises markdown / HTML / plain-text into a stable canonical
  form so LLM workflows get identical inputs regardless of format
  wrapping.
- **`electronipccheck`** -- lint for Electron IPC surface hygiene
  (unfiltered messages between renderer and main; missing
  nodeIntegration flags; contextIsolation gaps). Extracts a
  primitive from arXiv 2607.20698 (deferred from 2026-07-26).
- **`ppatern`** -- Prolog-education mutation-pattern registry
  extracted from arXiv 2607.21193 (deferred from 2026-07-26); still
  too domain-specific for a general audience.

## Methodology this cycle

- arXiv `export.arxiv.org/api/query` for cs.SE, cs.CR, cs.PL and
  cs.AI-filtered-by-`abs:agent`, sorted by submitted-date
  descending; ~130 titles across the 2026-07-27 -> 2026-08-02
  window. No arXiv submissions on Aug 1-2 (weekend); the window is
  effectively 2026-07-27 -> 2026-07-30 for cs.SE / cs.CR.
- HN Algolia `search_by_date` for `"Show HN"` in the same window
  above 60 points; ~25 hits, mostly consumer / creator tools with a
  handful of developer-workflow signals.
- Triage filter unchanged from prior weeks: *can a small clean-room
  implementation actually be tested this run, without a hosted-model
  dependency?* Of ~130 arXiv titles surveyed and ~25 HN candidates,
  one (2607.26819) directly implied a small primitive we could ship
  at world-class quality this cycle. The rest are noted or deferred.

## Trust note

All ingested content was treated as untrusted data. No instructions
or recommendations from any abstract, README, or post were acted on;
every build decision was made from the curator's own judgment of the
signal. The clean-room provenance for `aicontribcheck` is
correspondingly narrow: the paper's *problem framing* was consulted,
its *method / benchmark / any reference code was not*. Detection
patterns were curated from widely-published open-source contribution-
policy conventions (Developer Certificate of Origin; SPDX License
List identifiers; Creative Commons BY-NC summary; typical
`CONTRIBUTING.md` wording in mature FOSS repositories) -- not from
the paper.
