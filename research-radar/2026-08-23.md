## What we chose to build, and why

**One artifact this week**, holding the standing "quality over quantity" bar:
one world-class primitive beats three mediocre ones. The batch contains
`oraclecheck` and nothing else.

**`oraclecheck`** -- offline AST linter for Python test files that detects
**state-anchored oracles**: assertions whose expected value flows, directly or
transitively, from the code under test itself. Zero-dep Python stdlib, MIT.
Direct response to the frontier signal at [1] below: arXiv 2608.17214
("Oracles That Cannot Fail: The Anchoring Problem", 2026-08-17) shows that
"a test oracle that obtains its expected value from the system it is judging
cannot fail" -- if a fault moves measurement and expectation together, the
comparison cancels exactly. On a deployed air-traffic-control simulator (12
model-free property suites, 4 modules, 366 mutants), re-anchoring one holding
oracle to a published procedure -- with no production-code change -- recovered
8 of 46 previously-missed mutants. Existing lint tooling (ruff, pylint,
flake8) has no rule for state-anchored oracles because the smell is
semantic-over-test-structure, not syntactic; `oraclecheck` is the small
offline pre-flight primitive that fills that gap.

Ten documented rules: self-comparison (ORACLE-001, HIGH), direct anchor with
identical args (ORACLE-002, HIGH), tautological round-trip on self
(ORACLE-003, MEDIUM), snapshot-from-SUT with differing args (ORACLE-004,
HIGH), identity oracle (ORACLE-005, HIGH), repr/str round-trip on self
(ORACLE-006, MEDIUM), fixture-from-SUT (ORACLE-007, MEDIUM), mock-echoes-input
(ORACLE-008, MEDIUM), assertion-under-except-pass (ORACLE-009, HIGH), and
vacuous condition (ORACLE-010, INFO). Rules 002 and 004 are mutually exclusive
by construction (identical-args vs differing-args snapshot); rules 001 and 005
are mutually exclusive on `assertIs` and bare `assert x is x` (identity
belongs to 005). Per-file SUT hint is inferred from the filename
(`tests/test_foo.py` -> `foo`); overridable via `--sut`.

144 tests: 30 parser tests (ast helpers over Name / Attribute chain / Call /
Compare / Constant / Await / Assign / BOM handling / literal-truthy matrix),
40 rule tests (registry completeness + description non-empty + per-rule
positive-and-negative for all ten + 002/004 disjointness + 001/005
disjointness on `assertIs` and bare `is` + disabled-rule respect + sort-order
by severity-then-path), 20 scanner tests (SUT-inference matrix + discovery
canonical-and-suffix + case-insensitive + custom-glob + max-files cap +
deterministic order + missing-path + single-file singleton + read utf-8 + BOM
stripped + latin-1 fallback + missing-file + max-bytes truncation +
empty-directory + healthy-file + anchored-file + syntax-error-does-not-crash),
20 verdict-and-report tests (rollup healthy / needs-attention / unhealthy /
unknown-default / unknown-strict / high-overrides-medium / info-default-healthy
/ info-strict-escalates + JSON parseable and deterministic + text-includes-
verdict-line + info-hidden-by-default + findings-visible-sorted-by-severity +
error-lists-populated), 14 CLI tests (`--version` exit 0 + missing-path stderr
exit 2 + healthy-dir exit 0 + unhealthy-dir exit 2 + no-files default exit 1 +
no-files strict exit 2 + JSON parseable + include-info surfaces INFO in text +
default-path-is-cwd + `--disable` suppresses a rule with round-trip through
strict + `--max-files 0` stderr exit 2 + single-file path + `--sut` flag
enables 002), and 20 end-to-end fixture tests across the seven fixture shapes
(healthy / anchored / identity / swallow / mock / vacuous / unknown) with
JSON-roundtrip-determinism verification.

The lab's hygiene-linter family previously covered file-contents hygiene
(`envcheck`, `jsonlcheck`, `jwtcheck`), eval-stream hygiene (`jsonldiff`,
`jsonlsample`), install-manifest hygiene (`reqcheck`), license-chain hygiene
(`licensechain`), contribution-policy hygiene (`aicontribcheck`), agent-skill
*safety* hygiene (`skillcheck`), and agent-instruction *maintainability*
hygiene (`agentmdlint`). `oraclecheck` adds the **test-oracle-shape** layer:
the orthogonal question to "does the code work?" is "does the test have any
chance of catching the case where it does not?". Same pre-flight surface,
different failure mode.

Secondary candidates considered this cycle: `docagentcheck` primitive from
arXiv 2608.20195 (Agent Behaviour to Agent-Friendly Documentation; deferred

## Signal we noted (not built this week)

1. **Oracles That Cannot Fail: The Anchoring Problem** (arXiv 2608.17214,
   2026-08-17). Names *oracle anchoring* as a distinct test-smell class:
   state-anchored oracles cannot fail because the expected value flows from
   the same code being mutated. Measured on a deployed ATC simulator (12
   property suites, 4 modules, 366 mutants): re-anchoring one holding oracle
   on published procedure, changing no production code, recovered 8 of 46.
   The paper's *framing* is the direct motivation for `oraclecheck`; the
   paper's methodology, subject system, and any reference measurement code
   was NOT consulted.
   [arXiv](https://arxiv.org/abs/2608.17214)

2. **Agent Behaviour to Agent-Friendly Documentation** (arXiv 2608.20195,
   2026-08-20). Behaviour-grounded study across 557 agentic coding sessions
   (94,813 events, 3,033 doc interactions) plus 33,097 agentic PRs (690,260
   file-level records) reports an actionability gap (0.002 transition
   probability from docs to code) and a verifiability gap (0.23 lift on
   testing after doc consultation). Signals `docagentcheck` as a candidate
   primitive but "agent-friendly" is fuzzy for a small AST tool -- deferred.
   [arXiv](https://arxiv.org/abs/2608.20195)

3. **Outcome Monitors: Recovery Affordances** (arXiv 2608.19303, 2026-08-19).
   Coding agents consume cached errors as fact and lose recovery affordances
   when tools return silent-failure-in-expected-format outputs. Signals an
   `outcomemonitor` primitive; deferred because a useful implementation
   requires a live tool-output stream rather than a static file surface.
   [arXiv](https://arxiv.org/abs/2608.19303)

4. **Auditing Feedback-Driven Evolution in LLM Test Generation** (arXiv
   2608.19626, 2026-08-20). Single-reference oracles inflate reported gains;
   execution feedback on one implementation manufactures spurious
   fault-detection signals. Complementary framing to 2608.17214: 17214 is
   about anchoring within a single suite; 19626 is about
   feedback-loop-amplified false-positives across a training corpus. Both
   argue for external, specification-anchored oracles as the fix.
   [arXiv](https://arxiv.org/abs/2608.19626)

5. **Jagged Frontier: Code Agent Robustness to Semantics-Preserving
   Transforms** (arXiv 2608.18389, 2026-08-18). Coding agents rank-reorder
   under semantics-preserving code variations; robustness rankings differ
   across frameworks and models. Signals a `sptcheck` primitive that scans a
   codebase for high-variance-response shapes (renamed identifiers,
   reformatted-but-equivalent bodies); deferred pending a corpus of
   canonicalized SPT operators.
   [arXiv](https://arxiv.org/abs/2608.18389)

6. **One Gate Is Not Enough: Composing Pre-Action Controls** (arXiv
   2608.18360, 2026-08-18). Multi-gate agent controls (authority, resource,
   evidence) interact non-orthogonally; remediation by one invalidates
   others' judgments. Signals an audit primitive for gate-composition
   configurations; too abstract for a small AST tool without a target
   config-file surface.
   [arXiv](https://arxiv.org/abs/2608.18360)

7. **TRUSS: Task-Reliable, User-Safe Skill Generation** (arXiv 2608.17588,
   2026-08-18). Reinforces the `skillcheck` direction: agent skills are
   currently evaluated only by artifact or outcome, not by "which actions did
   the agent perform and what side effects did they produce?". No new
   buildable shape this week beyond what `skillcheck` already covers on the
   safety surface.
   [arXiv](https://arxiv.org/abs/2608.17588)

8. **What Makes Issue Resolution Tasks Difficult** (arXiv 2608.18280,
   2026-08-18). Task difficulty is not predictable from static properties;
   difficulty predictor is itself a research question. Interesting empirical
   framing; no small-primitive shape.
   [arXiv](https://arxiv.org/abs/2608.18280)

9. **Item-Level Regressions in LLM API Migrations** (arXiv 2608.17719,
   2026-08-18). Aggregate benchmark scores mask bidirectional item-level
   change during model migrations; migration decisions miss substantial
   capability variations. Signals an `itemdiff` primitive that computes
   per-item verdict-flip counts between two eval-run JSONLs; deferred (close
   to `jsonldiff` scope; would want the two-run correlation shape rather
   than a simple diff).
   [arXiv](https://arxiv.org/abs/2608.17719)

10. **Benchmarking Automated Security Patch Backporting** (arXiv 2608.17671,
    2026-08-18). Patch-backporting tools report 80%+ success on narrow test
    beds; cross-version and cross-repo generalization is poor; complex
    patches fail sharply. Signals downstream `backporthonest` primitive that
    reads a claim + a targeted test corpus and reports success-conditional-
    on-scope. Too heavy for a stdlib primitive this cycle.
    [arXiv](https://arxiv.org/abs/2608.17671)
