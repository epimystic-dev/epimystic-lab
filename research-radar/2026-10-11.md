### `agentmemcheck` -- static linter for agent memory-store files

Two independent 2026 signals converged on the same surface - the
**agent memory-store write boundary** - and together establish a
current unmet need the lab's hygiene-linter family can serve directly.

1. **OWASP Top 10 for Agentic Applications 2026** formally recognises
   **ASI06 Memory and Context Poisoning** as a deployment-relevant
   attack class, naming it alongside shared-memory multi-agent
   frameworks where one agent's writes turn into another agent's
   reads. The slot was promoted into the Top 10 on empirical grounds
   through 2026-H1; the formal recognition fixed the attack-class
   taxonomy around the write-time surface.

2. **The 2026 LLM-agent memory-poisoning research corpus** - eight
   independent papers between 2026-05 and 2026-08 - converge on the
   same shape surface:
   - *Hidden in Memory: Sleeper Memory Poisoning in LLM Agents*
     (arXiv 2605.15338): sleeper-dormancy threat class.
   - *When Agents Remember Too Much* (arXiv 2607.06595): GhostWriter
     attack, injection then activation across sessions.
   - *MemPoison: Bypassing Selective Memory Mechanisms to Plant
     Backdoors in LLM Agents* (arXiv 2605.29960).
   - *Your Agent's Memories Are Not Its Own: Forged Reasoning Attacks
     on LLM Agent Memory and Defenses* (arXiv 2607.05029): FARMA
     (Forged Amplifying Rationale Memory Attack).
   - *From Untrusted Input to Trusted Memory: A Systematic Study of
     Memory Poisoning Attacks in LLM Agents* (arXiv 2606.04329).
   - *Injection-Execution Dissociation: A Mechanistic Evaluation of
     Persistent Memory Attacks and Defenses in Stateful LLM Agents*
     (arXiv 2605.08442).
   - *Securing LLM-Agent Long-Term Memory Against Poisoning:
     Non-Malleable, Origin-Bound Authority with Machine-Checked
     Guarantees* (arXiv 2606.24322).
   - *MemSecBench: Tracking Agent Memory Poisoning from Persistence
     to Consequence and Repair* (arXiv 2607.27080).
   - *Utility Under Attack: Agent Memory Poisoning and the Limits of
     Content Screening and Provenance Ranking* (arXiv 2608.21230).

The two signals land on the same trust boundary - the write at which
untrusted-origin content enters long-term memory and acquires a
retrieval key - and the lab's existing linter family does not yet
cover it. `elevatescan` scans arbitrary agent-ingested content for
injection shapes before it enters a prompt template; `agentmemcheck`
scans the structured memory record itself after a write and before
retrieval. The two tools target distinct surfaces across the same
threat class.

The linter flags twelve shape defects: hidden-character concealment
in content (AMC-001, the Plane 14 TAG / bidi / zero-width / control /
PUA family); missing origin / source field (AMC-002, the
non-malleable origin-bound-authority requirement from arXiv
2606.24322); external-origin content stored at elevated role
(AMC-003, the core untrusted-input-to-trusted-memory promotion
surface); FARMA-shaped reasoning / rationale block (AMC-004);
credential-shaped literal in content (AMC-005, JWT / AWS / GitHub /
PEM / bearer); instruction-shape content from external origin
(AMC-006); duplicate memory ids (AMC-007, the backdoor-plant pattern);
missing TTL / expiration (AMC-008, the sleeper-dormancy surface named
by arXiv 2605.15338); cross-script homoglyph in an identifier field
(AMC-009); implausible timestamp (AMC-010); oversized content
(AMC-011, exfiltration staging); and missing `schema_version`
(AMC-012, silent-change detection).

5 HIGH / 5 MEDIUM / 2 INFO. 135 tests pass under
`python -m unittest discover -s tests`. Independent implementation,
not affiliated with or endorsed by OWASP or by the authors of any
cited paper.

### Why one, not three

Two secondary candidates were considered and set aside this week:

- A static linter for AI coding-assistant **rules files**
  (`.cursorrules` / `.mdc` / `.clinerules`) based on the Cloud
  Security Alliance research note *Hidden Unicode Instruction
  Injection in AI Agent Skills* (2026-03-10). The hidden-byte surface
  is already covered on skill files by `skillcheck` and on MCP tool
  descriptors by last week's `mcptoolcheck`; the rules-file surface
  is covered on maintainability grounds by `agentmdlint`. The gap -
  invisible-byte concealment inside the rules-file class specifically
  - is narrower than the gap `agentmemcheck` closes, and the shipped
  tooling already catches the same bytes if the rule files happen to
  be scanned alongside skill files.

- A static linter for the **MessageRole / Cross-Scope Context
  Privilege Escalation** surface named in arXiv 2609.01222 (*What's
  in Your Agent's Context?*). The paper's framing is runtime (what
  reaches which message role at inference time); the static surface
  is message-history traces, which overlap heavily with `elevatescan`.
  A clean sibling needs a stabler config-level artifact to lint
  against than the paper currently provides.

The lab's bar is "concrete, current problem, world-class for its
size, fully tested, this run." `agentmemcheck` cleared it; the two
secondaries did not.

Links are to the primary source. Items are weighed on real-signal
quality, not stars or point count. "Why this matters" is a
one-sentence lab-angled note; it does not reflect the authors' own
framing.

1. **arXiv 2605.15338** -- *Hidden in Memory: Sleeper Memory
   Poisoning in LLM Agents*.
   https://arxiv.org/html/2605.15338v2
   *Why this matters:* names the sleeper-dormancy threat class
   agentmemcheck AMC-008 (missing TTL) targets.

2. **arXiv 2607.05029** -- *Your Agent's Memories Are Not Its Own:
   Forged Reasoning Attacks on LLM Agent Memory and Defenses*.
   https://arxiv.org/html/2607.05029v1
   *Why this matters:* FARMA attack - a reasoning block containing a
   forged tool-call shape is the ground for AMC-004; the paper also
   notes OWASP's formal ASI06 recognition.

3. **arXiv 2607.06595** -- *When Agents Remember Too Much: Memory
   Poisoning Attacks on Large Language Model Agents*.
   https://arxiv.org/html/2607.06595v1
   *Why this matters:* GhostWriter attack - the two-phase
   injection-then-activation pattern justifies the write-time
   shape-check approach the whole linter embodies.

4. **arXiv 2606.04329** -- *From Untrusted Input to Trusted Memory:
   A Systematic Study of Memory Poisoning Attacks in LLM Agents*.
   https://arxiv.org/pdf/2606.04329
   *Why this matters:* systematic basis for AMC-003 (external-origin
   content at elevated role).

5. **arXiv 2606.24322** -- *Securing LLM-Agent Long-Term Memory
   Against Poisoning: Non-Malleable, Origin-Bound Authority with

   https://arxiv.org/html/2606.24322
   *Why this matters:* names the non-malleable origin-bound
   authority requirement; direct ground for AMC-002 (missing origin).

6. **arXiv 2605.29960** -- *MemPoison: Bypassing Selective Memory
   Mechanisms to Plant Backdoors in LLM Agents*.
   https://arxiv.org/html/2605.29960
   *Why this matters:* backdoor-plant pattern cited by AMC-007

7. **arXiv 2607.27080** -- *MemSecBench: Tracking Agent Memory
   Poisoning from Persistence to Consequence and Repair*.
   https://arxiv.org/pdf/2607.27080
   *Why this matters:* evaluation benchmark that would be the

8. **arXiv 2608.21230** -- *Utility Under Attack: Agent Memory

   https://arxiv.org/pdf/2608.21230

9. **arXiv 2605.08442** -- *Injection-Execution Dissociation: A
